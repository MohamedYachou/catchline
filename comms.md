## Communication protocol — every prompt

1. Read this file before work.
2. Append a **START** entry before editing: agent, prompt/task ID, intent, paths/model names, expected delivery and integration needs.
3. Append a **DONE** entry when finished: actual changes, commit, validation, preview/report paths, unfinished work and what the other Codex needs to do. Use **PARTIAL/BLOCKED** honestly when appropriate.
4. Preserve the other agent's entries. Append new entries rather than rewriting their history. Keep this main-project file authoritative even while working in the art worktree.
5. Windows Codex appends an integration acknowledgement with the accepted art commit and native Unity result. An asset delivery is not a claim of gameplay integration.
6. Each START also states exact write reservations, planned checks, collaborators
   and subagent scopes. Record changed scope/delegation in an UPDATE immediately.
7. Each closing entry lists actual files/artifacts/checks, native checks still
   pending, commit or no commit, lead/subagent state and explicit released/held
   reservations. Describe what another agent may pick up and what is actively owned.
8. When Mo says stop or asks for pickup, append STOPPED/PARTIAL with a usable
   checkpoint and release stopped reservations. Do not auto-resume historical work.
   The latest status for each task supersedes its START; DONE/idle does not hold files.
9. The lead owns logging delegated work here. Subagents append their own START/DONE
   when instructed, and the lead consolidates their status/results. No separate
   comm file should compete with this canonical log.
10. Keep ordered step IDs and CHECKPOINT during a turn: last VERIFIED step/evidence,
    implemented-but-UNVERIFIED work, IN PROGRESS step and exact next action. Mark
    each step before starting and checkpoint after meaningful safe boundaries.
11. Pickup starts at the first unfinished step, checking its actual code/artifacts.
    If Codex 1 verified D and stopped during E, Codex 2 checks/finishes E then F.
    Do not redo A–D unless dependencies/evidence require it. Missing completion
    does not mean the interrupted agent wrote nothing. Log scope-specific takeover.
